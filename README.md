# НОКТЕНА · премиальный редизайн

Статическая витрина, каталог на JSON с динамическими переопределениями, защищённая `/admin/` и отдельный Railway proxy. Рабочий URL, API, авторизация и схема БД сохранены. Премиальная версия размещена из ветки `main` через GitHub Pages на `noktena.ru`; рабочая ветка изменений — `premium-redesign`.

## Структура

| Путь | Назначение |
| --- | --- |
| `index.html` | Главная, категории и каталог через существующие hash-маршруты |
| `product.html` | Карточка товара и выбор варианта |
| `checkout.html` | Корзина и оформление заказа |
| `assets/design-system.css` | Общие цвета, типографика, фокус и доступность |
| `assets/*-2026.css` | Стили витрины, товара и заказа поверх имеющихся компонентов |
| `assets/catalog-v2.js`, `assets/product-detail.js`, `assets/checkout.js`, `assets/cart.js` | Каталог, карточка и заказ |
| `admin/` | Актуальная защищённая админка; `admin-v2/` сохранена как старый маршрут |
| `admin/store-settings.js`, `assets/contact-settings.js` | Контакты магазина, подборка на главной и смена пароля |
| `admin/site-settings.js`, `assets/seo-settings.js`, `assets/homepage-image.js` | Раздел «Настройки и SEO», метаданные и фотография главной страницы |
| `data/` | Базовый каталог |
| `railway-admin/` | Прокси к Supabase Edge Functions; в этом редизайне не менялся |
| `supabase/functions/noktena-admin-api/` | Исходник защищённого метода смены пароля действующего API |
| `supabase/functions/noktena-order-api/` | Проверка города и ассортимента при оформлении заказа |
| `tests/analytics.test.cjs`, `tests/store-settings.test.cjs`, `tests/site-settings.test.cjs` | Проверки без реальных заказов и смены рабочего пароля |

Контент товара остаётся в JSON и серверных переопределениях. Дизайн-система не создаёт собственную базу. SEO-заголовок и описание карточки можно заполнить через редактор товара; значения хранятся в текущем payload товара.

## Локальный запуск

```bash
cd noktena
python3 -m http.server 8765
```

Откройте `http://localhost:8765/`, `http://localhost:8765/product.html?kind=mattress&model=...`, `http://localhost:8765/checkout.html` и `/admin/`. Сервер должен открывать сайт по HTTP: `fetch` локальных JSON не работает через `file://`. Каталог читает публичный bootstrap, а вход в админку требует действующей учётной записи. Локальный checkout по умолчанию обращается к рабочему API; **не отправляйте тестовый заказ без отдельного тестового backend**.

Сборщика у витрины нет. Проверка исходников:

```bash
for f in assets/*.js admin/*.js; do node --check "$f" || exit 1; done
node --test tests/analytics.test.cjs
# Для проверки серверной функции TypeScript требуется Node.js 24:
node --experimental-strip-types --test tests/store-settings.test.cjs
node --experimental-strip-types --test tests/site-settings.test.cjs
```

В `/admin/` откройте «Контакты», чтобы поменять телефон и ссылку MAX, а также добавить ссылки Telegram, WhatsApp и VK. Заполненные дополнительные каналы показываются с локальными фирменными SVG в разделе контактов главной страницы, её подвале и блоке консультации карточки товара; пустые или удалённые ссылки скрыты. Новые значения появятся на страницах после их обновления. «Популярные модели» задают до шести товаров в нужном порядке; до первого сохранения используется прежняя автоматическая подборка. «Пароль» требует текущий пароль; после смены потребуется войти заново. Пароль хранится и изменяется в Supabase Auth, а не в исходниках или каталоге.

Раздел «Настройки и SEO» объединяет переходы к этим настройкам, ценам и доставке. В нём можно менять `title` и `description` главной страницы с предварительным просмотром. Значения сохраняются через защищённый API в `settings:seo_v1`; на главной они заменяют метаданные при выполнении JavaScript. Товарные заголовки и описания редактируются в карточках. GitHub Pages отдаёт исходный HTML с прежними метатегами до выполнения JavaScript, поэтому робот без рендеринга JavaScript может их не увидеть; для гарантированного серверного HTML требуется отдельная сборка или серверный рендеринг.

В этом же разделе есть отдельное «Изображение на главной». Администратор загружает JPEG, PNG или WebP до 12 МБ либо указывает публичную HTTPS-ссылку, видит предпросмотр и нажимает «Сохранить изображение». Настройка хранится в `settings:hero_v1` через существующий защищённый API и появляется на главной после обновления страницы. «Вернуть исходное фото» выбирает исходную фотографию; затем нужно сохранить. Это отдельная настройка от OG-картинки и фотографий товаров. Если заданный адрес недоступен, витрина показывает исходную фотографию.

### Города и каталоги

В `/admin/` откройте «Города и каталоги», введите название города и нажмите «Добавить город». Новый город создаётся с пустым ассортиментом; Екатеринбург сохраняет прежний каталог. Для выбранного города отметьте нужные позиции и сохраните. Можно скопировать ассортимент Екатеринбурга, затем убрать отдельные позиции. Кнопка «Изменить для города» открывает привычный редактор карточки: размеры, цвета, цены, описание и фотографии сохраняются только для этого города. «Создать товар для города» добавляет отдельную карточку.

Выберите дополнительный город и нажмите «Удалить город», чтобы после подтверждения убрать его товары, описание и стоимость доставки с сайта. Екатеринбург удалить нельзя. Уже оформленные заказы останутся в разделе «Заказы»; покупатель, оставшийся на странице удалённого города, получит сообщение о его недоступности при попытке оформления заказа.

В блоке «Описание города на сайте» можно изменить тексты первого экрана, доставки, разделов «Сервис» и «О нас», а также title и description главной для выбранного города. Поля сохраняются вместе с названием города в `settings:city_catalogs_v1`. Пустое поле возвращает прежний текст Екатеринбурга или автоматически сформированный текст другого города. Городские SEO-поля имеют приоритет над общей настройкой SEO на главной странице этого города; SEO карточек товаров редактируется отдельно.

Для массовой загрузки скачайте пустой CSV-шаблон либо выгрузите каталог города. В CSV одна строка означает один размер и цвет товара; строки с одинаковым `key` (или названием и типом, если `key` пустой) объединяются в карточку. Столбцы: `key;type;name;size;price;color;description;image`. Тип: `mattress`, `beds` или `sofas`. Изображения можно указать HTTPS-ссылками через `|`, а фотографии с компьютера загрузить позднее в редакторе карточки. Для повторного обновления товара используйте тот же `key`; пустой ключ создаёт постоянный ключ на основе названия и города. JSON-файл принимает массив товаров или `{ "items": [...] }` с полями `type`, `name`, `key`, `variants: [{ "size": "...", "price": 12000, "color": "..." }]`, `images`, `description`. После выбора файла админка показывает число моделей и размеров; «Добавить и обновить» сохраняет существующие товары города, «Заменить каталог» оставляет только товары файла. Перед заменой скачайте текущий CSV.

Покупатель выбирает город в верхней части сайта. Витрина, карточки и корзина показывают ассортимент выбранного города; разные города имеют отдельные корзины. Оформление заказа проверяет на сервере, что все позиции входят в каталог города. Стоимость доставки для дополнительного города задаётся в отдельном блоке «Стоимость доставки для города»: выберите город, укажите целое число рублей и нажмите «Сохранить стоимость». 0 ₽ означает бесплатную доставку; пустое поле — стоимость уточнит менеджер, а сумма заказа будет показана без доставки. Для Екатеринбурга действует общая настройка в разделе «Доставка». Указанная цена показывается на главной, в карточке товара и при оформлении заказа и проверяется сервером. Самовывоз доступен при указанном городе склада. Настройки хранятся в `settings:city_catalogs_v1` и входят в резервную копию настроек.

Оформленные заказы сохраняются в админке. В «Настройки и SEO → Уведомления о заказах» задаются адрес письма (по умолчанию `noktena@mail.ru`) и дополнительный канал: MAX, Telegram, оба или без мессенджера. Изменения применяются к новым заказам после сохранения. Кнопка «Отправить проверку» отправляет тестовые сообщения без создания заказа и показывает результат каждого канала. Почтовый пароль и токены ботов остаются только в переменных Railway. Ссылка на профиль MAX в контактах сайта не является получателем уведомлений: для автоматической отправки нужны бот и числовой ID пользователя либо чата.

Railway proxy отправляет уведомления после ответа покупателю; ошибка почты не отменяет сохранённый заказ. Одна лишь настройка SMTP не подтверждает доставку: предыдущая проверенная попытка завершилась тайм-аутом соединения. Перед тем как полагаться на почтовые уведомления, отправьте проверку из админки и убедитесь, что письмо пришло. При ошибке смотрите результат проверки и логи Railway. Фоновая отправка сейчас не имеет очереди повторных попыток; список заказов в админке остаётся источником истины.

Прокси запускается отдельно при необходимости: `cd railway-admin && npm ci && npm start` (Node.js 20+). Перед запуском сконфигурируйте переменные в окружении сервера; не добавляйте `.env` с секретами в Git.

## Переменные окружения прокси

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт HTTP, по умолчанию 3000 |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE` | Сервер уведомлений о заказах |
| `SMTP_USER`, `SMTP_PASS` | Учётные данные SMTP |
| `ORDER_EMAIL_TO`, `ORDER_EMAIL_FROM` | Адрес по умолчанию и отправитель письма; получателя можно изменить в админке |
| `MAX_BOT_TOKEN`, `MAX_CHAT_ID`, `MAX_USER_ID` | Токен бота MAX и необязательный ID получателя по умолчанию |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Токен бота Telegram и необязательный ID получателя по умолчанию |

Публичный адрес Supabase указан в proxy; приватные ключи и пароли в этом репозитории не требуются. Доступ администратора проходит через существующий серверный API и Supabase Auth. Счётчик Яндекс Метрики: `112921323`, файл `assets/yandex-metrika-config.js`.

## Безопасное размещение

1. Сверьте ветку `premium-redesign` с `main`; проверьте разметку, фильтры, карточки, корзину и админку с отдельным тестовым backend.
2. Проверьте payload заказа и уведомления на тестовой среде. Рабочие товары и заказы не использовать для экспериментов.
3. Проверьте Performance, Accessibility, Best Practices и SEO в Lighthouse, а также Chrome, Safari, Firefox и мобильные браузеры. Целевые оценки из ТЗ пока не подтверждены измерениями.
4. По разрешению владельца от 25.09.2026 ветка уже размещена через `main` и GitHub Pages на существующем домене. Старый `main` сохранён в `pre-premium-2026-09-25`; для следующих изменений повторите ревью в `premium-redesign`, затем объедините в `main`. Railway/Supabase и DNS не перенастраиваются. Workflow `test-cart-services.yml` выполняет только проверки без создания заказов. Одноразовые workflow, способные переписать страницы, переведены в ручной запуск.
5. Закрытая версия Sites только для просмотра содержит `preview-guard.js`: она читает каталог, блокирует запись в рабочий API и не отправляет события Метрики. Это отдельная копия, не исходник для выкладки на `noktena.ru`. Старый `main` сохраняется в истории Git для отката.

## Ограничения и протокол проверки

Аудит и план — в `AUDIT.md`, результаты и список изменений — в `REDESIGN_REPORT.md`. В доступном окружении не было тестовой базы и учётной записи админа. Реальное создание заказа, сохранение карточки и смена статуса заказа на рабочей базе намеренно не выполнялись. Текущая схема оформления не сохраняет способ оплаты: его согласовывает менеджер после получения заказа. Добавление полноценного способа оплаты требует отдельного согласованного изменения серверного контракта.
